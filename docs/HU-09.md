# HU-09: Explorar el barrio

Como visitante, quiero consultar los productos de un barrio para descubrir artículos disponibles en mi comunidad.

**Criterios de aceptación**

1. El feed puede consultarse sin iniciar sesión.
2. Con `neighborhoodId`, el feed permite filtrar por barrio.
3. Una publicación retirada (`REMOVED`) no debe mostrarse como disponible.

Referencia: tablero de historias de usuario Trendy (HU-09).

---

## 1. Informe de verificación sobre `develop` (commit `9a1f813`)

### Verificación de cada criterio

| # | Criterio | API | Web |
|---|---|---|---|
| 1 | Consultar sin sesión | ✅ `GET /api/products` es público | ❌ El feed solo estaba en `/inicio`, que exige sesión |
| 2 | Filtrar con `neighborhoodId` | ⚠️ El parámetro se llamaba `neighborhood`, y `?neighborhoodId=` no era un filtro admitido por el DTO | ❌ No había selector de barrio |
| 3 | No mostrar `REMOVED` | ✅ El feed solo lista `AVAILABLE` y retirar invalida la caché | ✅ Usa el mismo feed |

### Debilidades encontradas

| Debilidad | Impacto |
|---|---|
| El filtro de barrio no se normalizaba, pero el barrio se guarda en minúsculas. | `?neighborhood=Granada` no devolvía resultados. |
| `productApi.feed()` no aceptaba filtros y pedía siempre 12 productos. | La web no podía filtrar ni paginar. |
| La sección «Cerca de ti» de `/inicio` mostraba lo más reciente de toda la ciudad. | El título prometía algo que no hacía. |
| El enlace para volver desde el detalle de un producto iba a `/inicio`. | Un visitante terminaba en la página de ingreso. |
| El producto `san-fernando` del seed estaba a unos 4,7 km del punto de ese barrio en el catálogo de la web. | Una demo por cercanía daba resultados confusos. |

### Fuera del alcance de HU-09

- **Módulo de barrios.** `neighborhoodId` sigue siendo un slug libre y el catálogo sigue en `web/src/lib/barrios.ts`. La HU no exige una entidad `Neighborhood` ni migración.
- **Barrio de la cuenta.** La cuenta no guarda un barrio. La web recuerda en el dispositivo el último barrio elegido en `/explorar`. Guardarlo en el perfil exige una migración y queda como una HU aparte.
- **Retirar desde la web.** No hay botón para retirar una publicación; se hace con `DELETE /api/products/:id`.

## 2. Cambios implementados

### Backend (`back/src/product`)

- **`dto/find-products-query.dto.ts`**
  - Añade `neighborhoodId`.
  - Mantiene `neighborhood` como alias obsoleto, para no romper a quien ya lo usa.
  - Recorta y pasa a minúsculas los dos parámetros, igual que al publicar.
- **`product.service.ts`**: `resolveNeighborhood` da prioridad a `neighborhoodId` y trata el valor vacío como «sin filtro». Lo usan el filtro y la clave de caché, así que las dos formas comparten entrada y un barrio vacío cuenta como `all`.
- **`product.controller.ts`**: Swagger documenta `neighborhoodId`, marca `neighborhood` como obsoleto y aclara que los productos `REMOVED` no aparecen.
- **`seed/seed-data.ts`**: el producto de `san-fernando` usa el punto del barrio en el catálogo.
- **Colección de Postman**: la petición principal del feed por barrio usa `neighborhoodId`; las demás siguen probando el alias.

Un barrio sin productos, o que no existe, responde 200 con la lista vacía.

### Frontend (`web/src`)

- **`pages/Explorar.tsx`** (nuevo, ruta pública `/explorar`)
  - Filtros de barrio, categoría y condición, con paginación de 12 en 12.
  - Los filtros viven en la URL (`/explorar?barrio=granada&categoria=hogar&condicion=USADO&pagina=2`), así que se pueden compartir. Un valor fuera del catálogo se trata como «sin filtro».
  - Muestra los estados de carga, vacío y error. Una respuesta lenta no reemplaza el resultado del filtro más reciente.
- **`pages/Inicio.tsx`**
  - «Cerca de ti» pasa a ser «Todos los productos», con lo más reciente de toda Cali.
  - El botón **Ver todos los productos** abre `/explorar` con la lista completa de la ciudad.
  - El botón nuevo **Productos de mi barrio** abre `/explorar` con el barrio recordado y se rotula con su nombre (por ejemplo, «Productos de Granada»). Si aún no hay barrio recordado, abre `/explorar` para elegirlo.
- **`components/ProductCard.tsx`** (nuevo): tarjeta compartida por `Inicio` y `Explorar`.
- **`lib/api.ts`**: tipo `FeedFilters`; `productApi.feed()` acepta filtros y sigue pidiendo 12 por defecto.
- **`lib/barrios.ts`**: `barrioGuardado` y `guardarBarrio` (`localStorage`, clave `trendy.barrio`).
- **`components/Brand.tsx`**: enlace «Explorar» en el encabezado, con y sin sesión.
- **`pages/Landing.tsx`**: botón «Explorar productos».
- **`pages/Producto.tsx`**: los enlaces de regreso van a `/explorar`, que también funciona sin sesión.
- **`index.css`**: clases `.filters`, `.pager` y `.feed-actions`.

### Pruebas

- `dto/find-products-query.dto.spec.ts` (nuevo): con la misma configuración del `ValidationPipe` global, cubre `neighborhoodId`, la normalización, un barrio repetido en la URL y los filtros desconocidos.
- `product.service.spec.ts`: filtro por `neighborhoodId`, alias y prioridad, barrio vacío, consulta siempre limitada a `AVAILABLE`, caché al retirar un producto y clave de caché compartida.
- `test/product.e2e-spec.ts`: filtro por `neighborhoodId` sin token y sin distinguir mayúsculas, y producto retirado fuera del feed.

## 3. Cómo probar

### Pruebas automáticas

```bash
cd back
npm run test:cov   # 25 suites, 268 pruebas
npm run test:e2e   # 4 suites, 54 pruebas; necesita la base de datos

cd ../web
npm run typecheck
npm run lint
npm run build
```

La web no tiene framework de pruebas. Su verificación fue manual, con un navegador automatizado sobre la aplicación real.

### Prueba manual con la API (sin token)

1. `GET /api/products?neighborhoodId=granada` → 200, solo productos de Granada.
2. `GET /api/products?neighborhoodId=GRANADA` → el mismo resultado.
3. `GET /api/products?neighborhood=granada` → el mismo resultado (alias).
4. `GET /api/products?neighborhoodId=no-existe` → 200 con `total: 0`.
5. Retira un producto con `DELETE /api/products/:id` (con token del vendedor) y repite la consulta: ya no aparece, y `GET /api/products/:id` responde 404.

### Prueba manual en la web

1. Sin sesión, abre la portada y pulsa **Explorar productos**: `/explorar` abre sin pedir ingreso.
2. Elige un barrio: la lista, el título y la URL cambian.
3. Combina categoría y condición, y usa **Quitar filtros**.
4. Con más de 12 productos, usa **Siguiente** y **Anterior**. Cambiar un filtro vuelve a la página 1.
5. Ingresa y abre `/inicio`: la sección se llama «Todos los productos» y el botón del barrio lleva el nombre del último barrio elegido.
6. Pulsa **Productos de …** y **Ver todos los productos**: abren `/explorar` con y sin el barrio.
