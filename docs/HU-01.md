# HU-01: Crear una cuenta

**Rol:** visitante · **Prioridad:** alta

Como persona nueva, quiero registrarme con correo y contraseña para tener una cuenta propia y participar en Trendy.

## Criterios de aceptación y cómo se cumplen

| # | Criterio | Implementación | Evidencia automatizada |
|---|---|---|---|
| 1 | Con datos válidos y correo único se crea un USER activo y se entrega un JWT | `POST /api/user/register` (`UserService.create`): el servidor fija `role = [USER]`, `isActive = true` y `verificationStatus = UNVERIFIED`; responde 201 con el perfil y el `token` | e2e `HU-01 · crea un USER activo y entrega un JWT válido` (usa el token en `/user/me`); unitarias `crea la cuenta como USER activa y sin verificar` |
| 2 | Si el correo ya existe: 409 sin duplicar | Se busca el correo normalizado (minúsculas, sin espacios) antes de insertar; la restricción UNIQUE cubre registros simultáneos (23505 → 409) | e2e `devuelve 409 si el correo ya existe, sin importar mayúsculas, y no duplica la cuenta` (cuenta filas en la base) |
| 3 | Datos inválidos o intento de asignar un rol: 400 | `RegisterUserDto` solo acepta `email`, `password` (8–12) y `fullName` (2–100); el `ValidationPipe` global (`whitelist` + `forbidNonWhitelisted`) rechaza `role`, `isActive`, etc. | `register.dto.spec.ts` (role, isActive, verificationStatus, campos desconocidos y 12 casos inválidos); e2e `devuelve 400 si intenta asignar role/isActive/verificationStatus y no crea la cuenta` |

## Web

`/registro`: valida en el navegador con las mismas reglas, muestra el 409 como «Este correo ya tiene una cuenta en Trendy» con enlace a iniciar sesión, guarda el JWT y lleva a `/inicio` con un mensaje de bienvenida.

## Validación manual

1. Abrir `/registro`, crear una cuenta nueva: se entra a «Mi Trendy» con el rol Usuario y «Sin verificar».
2. Repetir con el mismo correo en mayúsculas: aparece el aviso de correo existente.
3. En Swagger, `POST /api/user/register` con `"role": ["ADMIN"]`: 400 `property role should not exist`.
