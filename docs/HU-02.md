# HU-02: Iniciar sesión

**Rol:** usuario registrado · **Prioridad:** alta

Como usuario, quiero autenticarme con mi correo y contraseña para acceder de forma segura a las funciones privadas.

## Criterios de aceptación y cómo se cumplen

| # | Criterio | Implementación | Evidencia automatizada |
|---|---|---|---|
| 1 | Credenciales correctas y cuenta activa: JWT de 1 hora | `POST /api/user/login`; `JwtModule` firma con `expiresIn: '1h'` | e2e `HU-02 · criterio 1` (comprueba `exp - iat = 3600`) |
| 2 | Correo inexistente, contraseña errónea o cuenta inactiva: 401 | `UserService.login` responde el mismo 401 en los tres casos, sin revelar cuál falló | e2e `HU-02 · criterio 2` (los tres casos); unitarias de `login` |
| 3 | Sin JWT válido o con token vencido: 401 en rutas protegidas | `@Auth()` + `JwtStrategy` (Passport) valida firma, vencimiento, cuenta activa y `tokenVersion` (cierre de sesión) | e2e `HU-02 · criterio 3` (sin token, token inválido y token vencido); `jwt.strategy.spec.ts` |

## Web

`/ingresar`: muestra «Correo o contraseña incorrectos» ante el 401. La sesión se guarda en el navegador y, al abrir la app con un token vencido o inválido, se descarta y las páginas privadas llevan a `/ingresar`.

## Validación manual

1. Ingresar con `demo@trendy.local` / `Trendy123` (seed): se abre «Mi Trendy».
2. Ingresar con una contraseña errónea: aparece el mensaje de error.
3. En Swagger, `GET /api/user/me` sin «Authorize»: 401.
