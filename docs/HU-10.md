# HU-10: Buscar por cercanía

Como visitante, quiero filtrar artículos por radio y ordenar por distancia para encontrar opciones cercanas a mi ubicación.

**Criterios de aceptación**

1. Con coordenadas y `radius` en km, el feed filtra productos dentro del radio.
2. La respuesta incluye la distancia al producto en `distanceKm`.
3. Con `sort=distance`, los resultados se ordenan por cercanía.

Referencia: tablero de historias de usuario Trendy (HU-10).

---

## 1. Verificación sobre `develop` (commit `ec6ecd0`)

| # | Criterio | API | Web |
|---|---|---|---|
| 1 | Filtrar por radio en km | ✅ `GET /api/products?lat=&lng=&radius=` usa `ST_DWithin` de PostGIS; el radio va de 0,1 a 50 km y vale 5 km por defecto | ❌ No había forma de pedirlo |
| 2 | `distanceKm` en la respuesta | ✅ Se calcula con `ST_Distance` y se redondea a 2 decimales; solo aparece si llegan coordenadas | ❌ El tipo `Product` no lo tenía y la tarjeta no lo mostraba |
| 3 | `sort=distance` | ✅ Ordena por distancia con desempate por id; sin coordenadas responde 400 | ❌ No había selector de orden |

La API ya cumplía los tres criterios, así que no se cambió el backend. La prueba e2e existente solo comprobaba que el primer resultado estuviera a menos de 1 km; faltaba demostrar el orden entre varios productos, el borde del radio y la paginación.

## 2. Cambios implementados

### Web (`web/src`)

- **`pages/Explorar.tsx`**
  - Selector **Ordenar por**, siempre visible: más recientes, menor precio, mayor precio, más vistos y más cercanos.
  - Al elegir **Más cercanos** sin ubicación, se abre el panel «¿Desde dónde buscamos?» con tres opciones:
    - **Usar mi ubicación:** pide el permiso del navegador.
    - **Un punto del mapa:** se toca en el mapa.
    - **Un barrio como centro:** desde el selector o tocando su marca en el mapa.

    El orden no cambia mientras no haya un centro.
  - **Barra de cercanía:** muestra el centro elegido, el deslizador de radio y las acciones **Cambiar ubicación** y **Quitar ubicación**.
  - **Barrio y cercanía son excluyentes:** elegir un barrio en el filtro quita la búsqueda por radio, y elegir un centro quita el filtro de barrio.
  - **Con un centro activo, los otros órdenes siguen filtrando por radio**, y cada tarjeta mantiene su distancia.
  - **Seguridad:** las coordenadas del dispositivo y de los puntos del mapa **no van en la URL de la página**. La URL solo guarda `orden`, `radio` y `centro`, que vale `mi-ubicacion`, `punto` o el slug de un barrio.
  - **Al recargar:** si el navegador ya dio permiso, la ubicación se recupera sola. Si no, o si el centro era un punto del mapa, se vuelve a pedir que se elija.
  - **Precisión de las coordenadas:** se redondean a 3 decimales (unos 110 m) antes de enviarse a la API.
- **`components/RadioSlider.tsx`** (nuevo)
  - El deslizador recorre una lista de radios de 0,1 a 50 km, más densa en los radios cortos.
  - Tiene marcas clicables en 1, 2, 5, 10, 20 y 50 km; en pantallas angostas se ocultan 2 y 20 para que no se monten.
  - Con el teclado avanza un valor por cada flecha.
  - El radio se aplica 350 ms después de soltar, para no lanzar una consulta por cada movimiento.
- **`components/MapaUbicacion.tsx`** (nuevo)
  - Mapa de OpenStreetMap con Leaflet.
  - Marca los barrios del catálogo y dibuja el radio a escala real.
  - Se carga de forma diferida: Leaflet solo se descarga si se abre el panel.
  - En modo oscuro, los mosaicos se invierten.
- **`lib/ubicacion.ts`** (nuevo): radios, lectura del radio desde la URL, ubicación del dispositivo con mensajes en español (permiso denegado, contexto no seguro) y consulta del permiso.
- **`lib/api.ts`**: `ProductSort`, y `lat`, `lng`, `radius` y `sort` en `FeedFilters`; `distanceKm` en `Product`.
- **`lib/format.ts`**: `distancia()`, que da «a 820 m», «a 2,4 km» o «menos de 50 m».
- **`components/ProductCard.tsx`**: muestra la distancia cuando la respuesta la trae.
- **`theme.css`**: estilos de la barra, el deslizador, el panel y el mapa, en modo claro y oscuro.
- **Dependencias:** `leaflet` y `@types/leaflet`.

### Pruebas (`back/test/product.e2e-spec.ts`)

Bloque «HU-10 · buscar por cercanía». Se publican tres productos a 0, 1,11 y 3,32 km de un punto, en un orden que no coincide con el de distancia:

- **Criterio 1:** con radio 1 km sale solo el más cercano, con 2 km salen dos y con 5 km los tres. Sin `radius` se usa 5 km, y `radius` 0 o 51 responde 400.
- **Criterio 2:** `distanceKm` vale 0, unos 1,11 y unos 3,32. Sin coordenadas, la respuesta no trae `distanceKm`.
- **Criterio 3:** con `sort=distance` el orden es del más cercano al más lejano, también al paginar de 2 en 2. Con coordenadas y `sort=recent`, se mantienen el filtro por radio y la distancia.

## 3. Cómo probar

### Pruebas automáticas

```bash
cd back
npm run test:cov   # 26 suites, 380 pruebas
npm run test:e2e   # 4 suites, 120 pruebas (6 de HU-10); necesita la base de datos

cd ../web
npm run typecheck
npm run lint
npm run build
```

La web no tiene framework de pruebas. Se verificó con un navegador automatizado sobre la aplicación real, simulando la ubicación con permiso concedido y con permiso denegado.

### Prueba manual con la API (sin token)

1. `GET /api/products?lat=3.3826&lng=-76.5296&radius=1&sort=distance` → el escritorio y la lámpara de El Ingenio, a unos 0,8 km, con `distanceKm` y en orden.
2. El mismo enlace con `radius=5` → aparecen también los dos productos de Ciudad Jardín, a unos 2,4 km.
3. Sin `lat`/`lng` → los productos no traen `distanceKm`.
4. `sort=distance` sin coordenadas, o `radius=0` → 400.

### Prueba manual en la web

1. Abre `/explorar` sin sesión y elige **Ordenar por → Más cercanos**.
2. Pulsa **Usar mi ubicación** y acepta el permiso. Las tarjetas muestran «a … m/km» y van de la más cercana a la más lejana, y la URL no contiene coordenadas.
3. Mueve el deslizador o pulsa una marca, por ejemplo «1 km»: la lista se reduce.
4. Cambia a **Menor precio**: el radio se mantiene y la lista se ordena por precio.
5. Pulsa **Cambiar ubicación** y toca un punto del mapa, o la marca de un barrio: el círculo y los resultados cambian.
6. Elige un barrio en el filtro **Barrio**: la búsqueda por cercanía se quita.

La ubicación del dispositivo solo funciona en `localhost` o con HTTPS; en un celular que abra la web por la IP local con `http`, usa el mapa o un barrio. El mapa necesita conexión a internet para cargar los mosaicos de OpenStreetMap.
